## 1. Executive Summary

Version 1.2.0 is a major milestone release that accomplishes three primary objectives requested by users:
1. **Full 43 Actions Parity**: Achieved 100% feature parity with the reference core (`swag-labs-hybrid/schema/actions.json`), expanding from ~24 actions to all 43 actions across UI, Assertions, API, Network, and Flow control.
2. **Strict Locator Repository Binding**: Added scenario-level locator repository binding constraint (`scenario.config.locatorFile`), strictly scoping Page Objects and locking element-requiring fields with clear visual warnings when unbound.
3. **Live Web Inspector & 1-Click Auto-Scraper for Non-Tech Users**: Integrated a Playwright-powered visual element picker and full-page interactive DOM scraper that automatically generates robust selectors and camelCase names directly into Page Objects.

### 2.2. Strict Locator Repository Binding Constraint
- **Problem Solved**: Scenarios previously allowed entering random element keys without binding to a locator file, and autocomplete mixed elements from all locator repositories in the workspace, causing run-time failures and confusing non-tech users.
- **Implementation**:
  - Added **"Bound Locator Repository"** dropdown to `ScenarioEditor.tsx` reading `scenario.config.locatorFile`.
  - When `!scenario.config?.locatorFile`:
    - An amber warning banner appears: *"⚠️ No Locator Repository Selected: Please select a locator repository in the header above."*
    - In `StepItem.tsx`, all element-requiring UI and Assertion actions automatically disable the `Page Object` and `Element Key` input fields with the placeholder `⚠️ Bind Locator Repo above first`.
  - When a locator file is selected:
    - Scopes `availablePages` and `locatorMap` **strictly** to that chosen file. Elements from unrelated files no longer pollute the suggestion list.
    - Fields instantly unlock and populate Page / Element datalists.
  - In `execution-service.ts`, the bound locator file name is passed to `ActionEngine` so any auto-healing updates occur directly in the bound file.

### 2.3. Interactive Studio Browser Companion & Live Screen Element Scraper
Designed specifically for enterprise & non-technical testing workflows where target screens require manual navigation, authentication, 2FA/SSO, session cookies, or dynamic modal popups.

- **Architecture & Workflow**:
  - **Launch Interactive Session (`launchSession`)**: Opens a persistent, headed Google Chrome / MS Edge browser window side-by-side with Desktop Studio. Users are completely free to navigate, log in with credentials, input OTP/2FA tokens, open menus, and reach the exact screen or popup they need.
  - **Real-time Navigation Tracking**: Automatically tracks the active tab's URL and title via `framenavigated` and `domcontentloaded`, updating Desktop Studio in real time.
  - **1-Click Live Screen Scraping (`scrapeCurrentScreen`)**: Evaluates DOM interactive element extraction directly on `this.activePage` at its current live state—without navigating away, without losing authentication cookies, and without reloading the page.
  - **Live Screen Hover & Click (`setPickerMode`)**: Toggles visual hover highlight on the live screen to click and capture specific elements.
  - **In-Page Floating Toolbar**: Injects an unobtrusive floating bar at the top right of the browser (`[🎯 Pick Elements] [⚡ Scrape Screen] [Studio Connected: PageObject]`) enabling testers to trigger scraping directly from the web page!
- **UI Enhancements (`ElementPickerModal.tsx`)**:
  - Live status indicator: 🟢 Connected to Screen vs 🔴 Disconnected.
  - One-click "Mở Trình duyệt Tương tác" and "Đóng Trình duyệt" buttons.
  - Live URL and page title display.
  - "⚡ Cào nguyên Screen hiện tại" and "🎯 Bật Pick Element" action triggers.
  - Discovered elements checklist with editable camelCase names, search filtering, and bulk import.
