# Release Report - Version 1.1.0: Workspace Flexibility & Multi-TestCase Isolation

**Release Date:** September 7, 2026  
**Build Target:** Windows x64 Portable Unpacked (`dist-release/win-unpacked/Playwright Embedded Studio.exe`)  

---

## 1. Executive Summary

Version 1.1.0 addressed critical architectural limitations identified by user testing:
1. Fixed workspace folder detection and prevented forced creation of unwanted nested `data/` directories.
2. Re-architected execution from monolithic step sequences into **Isolated Multi-TestCase Suites** with independent browser contexts and selective re-testing.
3. Added workspace management capabilities (deleting workspaces, removing recent items).
4. Solved Windows SmartScreen / Smart App Control publisher verification blocks using automated code-signing scripts.

---

## 2. Key Capabilities Implemented

### 2.1. Workspace Resolution & Custom Folder Support
- **Flexible Path Discovery**:
  - Automatically checks whether the selected folder already contains `scenarios/` and `locators/` directly, or under a `data/` subfolder.
  - Users can select their existing project folder without the app creating unexpected new files or overriding user data.
- **Workspace Workspace Operations**:
  - Added workspace folder deletion and removal from recent history directly in the UI.

### 2.2. Isolated Multi-TestCase Architecture
- **Schema Evolution (`IScenario` & `ITestCase`)**:
  - Scenarios now support structured `testCases: ITestCase[]`, each having:
    - `testId`: Unique identifier (e.g. `TC_01`, `TC_LOGIN_VALID`).
    - `testName`: Human-readable test title.
    - `preconditions`: Setup steps.
    - `steps`: Core scenario steps.
    - `postconditions`: Teardown / cleanup steps.
    - `dataTable`: Data-driven rows specific to the test case.
- **Clean BrowserContext per Test Case**:
  - Instead of sharing one dirty session, each test case executes in a brand new, isolated `BrowserContext`.
  - Cookies, local storage, session storage, and cache are completely cleared between test cases, preventing cross-test pollution.
- **Selective Re-Testing**:
  - Users can run a single specific test case (e.g. "Run TC_01") without executing the entire 20-minute suite.
  - Multi-select checkboxes allow selective execution of failed or modified test cases.

### 2.3. Test Case Step Count & Scenario Inspection
- Pre-execution scenario inspector displays the exact count of test cases and steps upfront in the UI sidebar and test runner before launching the browser.

### 2.4. Windows SmartScreen Code Signing
- Created `scripts/sign-exe.ps1` using `Set-AuthenticodeSignature` and self-signed code-signing certificates.
- Configured automated unblocking with `Unblock-File` to prevent Windows SmartScreen publisher warnings from blocking portable execution.

---

## 3. Verification & Metrics

- Verified that deleting a workspace properly removes the target folder or cleans history without runtime crashes.
- Verified test case isolation: Login state in `TC_01` does not persist into `TC_02`; each begins with a fresh browser window and clean cookies.
- Verified selective test case runner: Selecting `TC_02` only runs `TC_02` steps and produces a dedicated HTML execution report.
