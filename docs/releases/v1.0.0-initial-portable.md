# Release Report - Version 1.0.0: Initial Embedded Portable Desktop Studio

**Release Date:** September 6, 2026  
**Build Target:** Windows x64 Portable Unpacked (`dist-release/win-unpacked/Playwright Embedded Studio.exe`)  
**Core Origin:** Ported from `swag-labs-hybrid`  

---

## 1. Executive Summary

Version 1.0.0 marked the initial foundational release of **Playwright Embedded Desktop Studio**, transforming the CLI/Node-based `swag-labs-hybrid` testing framework into a standalone, zero-prerequisite Windows desktop application powered by Electron, React, Tailwind CSS, and `playwright-core`.

---

## 2. Key Capabilities Implemented

### 2.1. Standalone Runtime Packaging
- Embedded `playwright-core` and Chromium automation runtime directly within the application package.
- Removed external requirements: End-users do not need Node.js, npm, or Git installed on their machines.
- Leverages system-installed Google Chrome or Microsoft Edge to run automated tests with zero overhead.

### 2.2. Embedded ActionEngine Porting
- Extracted and ported execution engine from `swag-labs-hybrid`:
  - `ActionEngine.ts`: Core orchestrator dispatching steps to specialized handlers.
  - `UIActionHandler.ts`: Basic UI interactions (`goto`, `click`, `fill`, `press_key`, `hover`, `check`).
  - `AssertActionHandler.ts`: Visual assertions (`verify_visible`, `verify_text`, etc.).
  - `APIActionHandler.ts`: Basic HTTP requests (`api_get`, `api_post`, `api_delete`).
  - `LocatorManager.ts`: Resolves Page Object elements.
  - `DataManager.ts`: Resolves dynamic variables and data substitution.

### 2.3. Desktop Studio User Interface
- Modern dark-themed dashboard built with React, Lucide icons, and Tailwind CSS.
- **Scenario Studio**: Tabbed visual step builder with drag-and-drop support.
- **Locator Pool Studio**: Viewer and editor for JSON locator files.
- **Test Runner Panel**: Live execution monitor displaying real-time step progress, execution times, and status badges.
- **Standalone HTML Report Generator**: Generates clean, zero-dependency HTML test execution reports with error callouts and step timing breakdowns.

## 3. Initial Known Limitations & Feedback Identified

1. **Step-by-Step Flow Instead of Independent Test Cases**:
   - Initial scenarios ran as a single monolithic sequence of steps rather than isolated test cases.
   - If Step 5 failed, all subsequent steps in the scenario were affected, and test sessions shared the same browser cookies.
2. **Workspace Folder Overwriting**:
   - Selecting a custom workspace folder caused the app to generate a default `data` folder inside instead of loading existing user test cases properly.
3. **Limited Action Coverage**:
   - Only ~24 actions were available in the UI catalog compared to 43 actions in the reference core.
4. **Non-Tech Usability Barrier**:
   - Non-technical QA and business testers found it challenging to inspect DOM selectors manually using DevTools without a built-in visual element picker.
